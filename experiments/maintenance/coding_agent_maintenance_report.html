Open-source coding agents, July 8, 2026

The hard part is keeping a coding-agent ecosystem alive.

A coding agent demo can happen quickly. A coding agent that real users depend on becomes an ecosystem for software work: runtime and SDK layers, sandboxing, auth, model routing, browser and terminal control, UI, integrations, telemetry, releases, tests, and a steady stream of edge cases.

Thesis: Measure OpenHands as the public ecosystem it has become, then use peer harness repos as spot checks. The pattern is consistent: serious coding agents need sustained maintenance, large code surfaces, and a real contributor community.

The last 3 months alone: 2,007 merged PRs from 87 unique human contributors across the ecosystem.

High-Level Takeaways

The numbers point to maintenance as the real work: not just writing agent loops, but operating a complex product surface as models, tools, users, and environments keep changing.

1

Agents become platforms.

Every serious agent needs runtime isolation, provider plumbing, repo access, terminals, browsers, secrets, storage, APIs, and UI surfaces that explain what happened.

2

Fixes are not side quests.

For the OpenHands ecosystem, bug-fix PRs are roughly a third of merged work over 12 months. Reliability is a central product investment.

3

People are the scaling factor.

OpenHands saw 252 unique human PR contributors in a year. Mature agents require review, triage, release judgment, and community care.

4

The category is heavy.

Codex, OpenCode, and Hermes all show thousands of merged PRs. They are peer harness spot checks, not perfect apples-to-apples comparables.

Suggested Framing

Building your own coding agent is possible. Maintaining one for real users is a long-running engineering commitment across product, runtime, SDK, server, and interface surfaces.

  • Show the OpenHands ecosystem numbers first.
  • Use peers as spot checks, not a strict ranking.
  • Keep bug-fix work visible, not buried.
  • Center the people doing the work.

Method Notes

Merged PRs are treated as the contribution unit. Bug-fix PRs use labels containing bug, regression, defect, or crash, plus titles beginning with fix, bugfix, hotfix, or repair. LOC uses tracked files from shallow clones, excluding common lockfiles, generated/vendor directories, binary assets, and docs from the code LOC number.
